# Quality Framework Analysis

Reproducible statistical analysis of the reviewed recording-quality features
generated by [`quality_framework_features`](https://github.com/nevena-m3/quality_framework_features).
This repository starts from governed data and feature freezes; it does not extract
audio features or modify the upstream measurement algorithms.

## What this repository answers

The pipeline addresses four connected questions:

1. Did each feature family pass its declared analytical validation gates?
2. How common, variable, persistent, and clinically associated are the retained
   recording-quality indicators?
3. Which indicators represent distinct versus overlapping dimensions of recording quality?
4. How do signal-derived indicators correspond to independent human annotations,
   both at the family and individual-item levels?

The analysis preserves the distinction between recording-quality measurement,
clinical association, and diagnostic prediction. Cohort comparisons are interpreted
as acquisition/confounding structure—not diagnostic accuracy.

## Repository layout

```text
config/                 Family definitions and figure configuration
data/
  raw/                  Local links to governed upstream freezes (Git-ignored)
  derived/registries/   Regenerated input registries (Git-ignored)
docs/                   Detailed methods, data contract, and frozen plans
notebooks/              Seven canonical analysis notebooks, in execution order
outputs/                Regenerated tables/models/figures/manifests (Git-ignored)
scripts/
  setup/                Environment and Jupyter launch helpers
  review_packages/      Optional packaging helpers for scientific review
  preflight.py          Input and notebook validation
src/rq_analysis/        Reusable registry/path/figure code
```

Backups, placeholders, development runs, embedded notebook outputs, Python caches,
and the local virtual environment are deliberately excluded from the repository.

## Required upstream inputs

By default the repository expects this local arrangement:

```text
Paper_1/
  Codes/analysis_recording_quality/       this repository
  paper_1_cleanup/                        feature repository
    MAIN outputs/00_DATA_FREEZE/v1/
    MAIN outputs/02_FEATURE_REVIEWED/06_family_freezes/
Nevena_project/
  Data_13072026/Bamboo_passage_HumanQC/   four-rater annotations
```

Every path can be overridden without editing a notebook:

```powershell
$env:PAPER1_ANALYSIS_ROOT = "C:\path\to\quality_framework_analysis"
$env:PAPER1_PIPELINE_ROOT = "C:\path\to\quality_framework_features"
$env:PAPER1_DATA_FREEZE_DIR = "C:\path\to\00_DATA_FREEZE\v1"
$env:PAPER1_FAMILY_FREEZE_DIR = "C:\path\to\06_family_freezes"
$env:PAPER1_HUMAN_QC_ROOT = "C:\path\to\Bamboo_passage_HumanQC"
```

No participant-level data, human annotations, family freezes, or generated outputs
are committed to GitHub.

## Installation

Windows PowerShell:

```powershell
cd C:\path\to\analysis_recording_quality
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[notebooks,dev]"
python scripts\preflight.py
```

Alternatively, the setup helper creates the environment, links the reviewed family
freeze, builds the registries, and registers a Jupyter kernel:

```powershell
.\scripts\setup\setup_project.ps1
```

Use `environment.yml` if Conda is preferred.

## Running the pipeline

Open JupyterLab:

```powershell
.\scripts\setup\open_jupyter_lab.ps1
```

Then run notebooks from top to bottom in numeric order:

| Order | Notebook | Purpose | Main output subtree |
|---:|---|---|---|
| 1 | `01_validation_synthesis.ipynb` | Harmonize family validation evidence and build the validation figure. | `outputs/figures/`, `data/derived/registries/` |
| 2 | `02_extent_distribution_persistence.ipynb` | Availability, distributions, repeated-recording persistence, cohort and bulbar associations. | `outputs/extent_distribution_persistence/` |
| 3 | `03_multidimensional_structure.ipynb` | Between/within-participant dependence, redundancy, family contrasts, PCA, and sensitivities. | `outputs/multidimensional_structure/` |
| 4 | `04_human_annotation_audit.ipynb` | Parse and audit raw human annotation intervals; no signal correspondence models. | `outputs/goal3_human_correspondence/stage1_annotation_audit/` |
| 5 | `05_human_reference_reliability.ipynb` | Four-rater agreement, prevalence, temporal overlap, and harmonized human reference. | `outputs/goal3_human_correspondence/stage1b_human_reference_reliability/` |
| 6 | `06_family_human_correspondence.ipynb` | Family-matched signal–human correspondence with participant-aware support gates. | `outputs/goal3_human_correspondence/stage2_construct_matched_correspondence/` |
| 7 | `07_item_mapping_atlas.ipynb` | Exploratory item-feature mapping atlas and rater-stratified diagnostics. | `outputs/goal3_human_correspondence/stage3_item_mapping_atlas/` |

The long-running notebooks default to their frozen final settings (up to 2,000
bootstrap replicates and 10,000 permutations). For development only, set each
notebook's `FINAL_RUN = False`; never mix development outputs with final results.

## Rebuilding only the validation registries and figure

```powershell
.\scripts\run_validation_figure.ps1
```

## Reproducibility and review

Each major analysis writes source-data tables, model diagnostics, completion checks,
input/output inventories, and a frozen analysis specification. A run is not complete
merely because a figure was created: inspect the blocking completion checklist and
population audit in the corresponding output folder.

See [the detailed analysis guide](docs/ANALYSIS_GUIDE.md) for estimands, models,
guardrails, sensitivity analyses, and expected artifacts for every notebook.
